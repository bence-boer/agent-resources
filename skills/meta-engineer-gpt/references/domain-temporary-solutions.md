# Domain - Temporary solutions

## Use when

Use when the easiest path is a workaround, a staged approach, or a local exception that could ossify into policy.

## Route next

- [domain-maintainability.md](domain-maintainability.md) - to search for the smallest durable alternative
- [domain-risk-and-safety.md](domain-risk-and-safety.md) - if the shortcut hides meaningful downside
- [finish-self-review.md](finish-self-review.md) - to challenge any rationale that sounds like hope instead of a plan

## Questions

- Are you about to create a temporary solution with no believable payback plan? Examples: TODO branch, manual step, hardcoded exception
- If this workaround survives a year, how much damage does it do? Examples: hidden risk, churn, blocked extension
- What is the smallest durable solution instead? Examples: explicit config, shared helper, one real invariant
- If you must stage the work, what boundary keeps stage one honest? Examples: flag, adapter, isolated path
