# Domain - Completeness

## Use when

Use when the task changes a pattern that probably exists elsewhere or when finishing work feels suspiciously easy.

## Route next

- [foundation-definition-of-done.md](foundation-definition-of-done.md) - to compare the current state against the real finish line
- [domain-correctness-and-verification.md](domain-correctness-and-verification.md) - to prove all relevant paths were exercised
- [finish-self-review.md](finish-self-review.md) - to pressure-test whether anything meaningful still remains open

## Questions

- What adjacent work must happen for this change to be truly complete? Examples: migration, copy update, docs, cleanup
- What second-order effect will appear after the first fix lands? Examples: stale cache, missing audit, broken sort
- Which similar paths or mirrored experiences need the same treatment? Examples: create and edit, admin and user, API and UI
- What have you not verified yet because it is inconvenient? Examples: empty state, rollback, concurrent edit
