# Domain - User value

## Use when

Use when the change affects what people can do, feel, trust, or notice.

## Route next

- [domain-workflow-fit.md](domain-workflow-fit.md) - to place that value inside the surrounding journey
- [domain-error-handling.md](domain-error-handling.md) - to preserve trust when the ideal path breaks
- [finish-self-review.md](finish-self-review.md) - to ask whether the result actually feels worth it

## Questions

- What user, buyer, or operator outcome justifies this work? Examples: less waiting, fewer mistakes, more trust
- What detail would make the result feel thoughtful instead of transactional? Examples: clear wording, better defaults, fewer clicks
- What would disappoint the user even if the ticket is technically complete? Examples: missing status, awkward edge case, confusing state
- What tradeoff are you making on the users behalf, and is it the right one? Examples: speed vs clarity, power vs safety
