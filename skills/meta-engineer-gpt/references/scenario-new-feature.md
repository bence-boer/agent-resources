# Scenario - New feature

## Use when

Use when the task adds a capability rather than only correcting or reorganizing existing behavior.

## Route next

- [domain-user-value.md](domain-user-value.md) - to define why the feature deserves to exist
- [domain-workflow-fit.md](domain-workflow-fit.md) - to make the feature feel native to existing flows
- [domain-error-handling.md](domain-error-handling.md) - to design failure and recovery instead of bolting them on later
- [domain-maintainability.md](domain-maintainability.md) - to keep the new surface easy to extend

## Questions

- What new ability should users or operators gain, and why now? Examples: faster setup, fewer manual steps, better visibility
- How should this fit the existing product or workflow instead of feeling bolted on? Examples: same navigation, same language, same mental model
- What downstream behaviors, permissions, data, or support burden does this feature create? Examples: new state, more docs, more alerts
- What would make this feature feel complete on first release? Examples: clear empty state, safe defaults, obvious recovery
