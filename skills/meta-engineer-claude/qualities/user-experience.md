# User Experience — Does This Serve the User Well?

The user doesn't care about your code. They care about their task.

1. How does this feature integrate into the user's existing workflow and mental model? (e.g., consistent navigation, familiar patterns, logical placement)
2. What is the user actually trying to accomplish, and does this directly serve that goal? (e.g., not just implementing a spec, but solving the user's real problem)
3. What does the user see during loading, errors, and empty states? (e.g., skeleton screens, clear error messages, helpful empty states, progress indicators)
4. Does this work on every device and screen size the user might use? (e.g., mobile responsiveness, touch targets, viewport overflow, text wrapping)
5. Is the user ever left wondering what happened, what to do next, or why something failed? (e.g., missing feedback, unclear affordances, silent failures, ambiguous labels)
6. Based on the current workflows and use cases, what is the ideal flow that makes this feel seamless? (e.g., minimal clicks, logical order, smart defaults, keyboard shortcuts)
