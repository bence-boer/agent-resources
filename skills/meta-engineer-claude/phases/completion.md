# Completion — Before Declaring Done

A feature isn't done when the code works. It's done when nothing is left undone.

1. Is there any "I'll fix this later" or "good enough for now" lurking in my implementation? (e.g., TODO comments, hardcoded values, skipped edge cases, temporary workarounds)
2. Would someone reading my commit message and diff understand exactly what changed and why? (e.g., clear commit message, logical diff, no unrelated changes)
3. Have I updated every piece of documentation, type definition, and configuration that my change affects? (e.g., READMEs, API docs, env examples, generated types)
4. If my change requires manual steps, are those steps documented and verified? (e.g., migration instructions, environment variables, deployment runbook)
5. Am I leaving the code I touched in better shape than I found it? (e.g., clearer names, removed dead code, better error messages, improved types)
