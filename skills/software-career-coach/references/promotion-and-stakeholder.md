# Promotion and Stakeholder Alignment

Read this file when the user wants promotion, more visibility, better 1:1s, smarter skip-level use, or stronger translation of technical work into business value.

## Promotion Principles

- Promotion is usually earned by operating at the next level before the title changes.
- Managers are not mind readers; ambition must be stated explicitly and repeatedly.
- Evidence beats effort. Busy does not equal promotable.

## Split Rule

- Use this file for promotion mechanics, visibility, 1:1 execution, skip-level discipline, and stakeholder translation.
- Use [career ladders](career-ladders.md) when the missing question is level readiness, scope calibration, or track definition.

## Brag Document Fields

Track these continuously:

- project or initiative
- problem and business stake
- actions taken
- measurable results
- reliability, cost, or speed improvements
- mentoring or enablement impact
- stakeholder feedback
- artifacts produced: design docs, postmortems, migration plans

## Promotion Packet Mechanics

Build the packet around the target level, not around a random list of wins:

- target level and the next-level rubric criteria
- strongest evidence mapped to each criterion
- one or two anchor projects with metrics, artifacts, and business stakes
- stakeholder endorsements, feedback, or adoption signals
- known gaps plus a plan to close them
- review-cycle timing, sponsorship needs, and when to ask formally

## High-Leverage 1:1 Loop

Use 1:1s for career versioning, not status recaps:

- **Before:** bring 2-3 fresh evidence items, one scope ask, and one explicit promotion question.
- **During:** cover what is going well, where blockers exist, what scope you want next, what evidence is still missing, and what introductions or sponsorship would help.
- **Ask directly:** "What evidence is still missing for promotion?" and "What next-scope opportunity should I own?"
- **After:** record commitments, owners, and the next review date instead of relying on memory.

## Three Circles of Impact

Coach the user to frame work in three layers:

1. **Individual contribution:** code, systems, incident response, delivery
2. **Collaboration:** cross-functional execution, code review quality, coordination
3. **Enabling others:** mentoring, documentation, tooling, process improvements

Promotion cases get stronger as the third circle expands.

## Skip-Level Rules

- Use skip-level meetings for strategic context, upward feedback, and understanding company direction.
- Stay transparent with the direct manager.
- Never use skip-levels as a private complaint channel for ordinary team friction.

## Translating Technical Work for Non-Technical Stakeholders

Move from feature language to outcome language:

- technical change
- user or operator effect
- business metric or risk outcome

Example:

- "We moved to a more resilient event pipeline" becomes
- "We reduced checkout failures during peak traffic, protecting revenue and support capacity."

## Coaching Moves

- If the missing question is readiness or level definition: load [career ladders](career-ladders.md).
- If the user is invisible: build a packet and narrative.
- If the user is visible but underscoped: acquire a bigger problem.
- If the user has scope but weak business fluency: practice executive translation.
- If politics are the blocker: focus on sponsorship, trust, and cross-functional credibility rather than louder self-promotion.
