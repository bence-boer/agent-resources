# Interview Loop Preparation

Read this file when the user needs help with coding interviews, take-homes, system design, behavioral loops, or how to use reverse-interview time well inside a live loop.

## Interview Funnel

| Stage | What it tests | Coaching focus |
| --- | --- | --- |
| Online assessment | data structures, algorithms, speed under constraints | pattern recognition, fluency in chosen language |
| Take-home | practical design, code quality, testing, communication | scope control, README quality, tests, trade-off explanation |
| Live screen | problem solving and communication in real time | narrating thought process, edge cases, complexity discussion |
| System design | architecture, trade-offs, scaling judgment | requirements, bottlenecks, storage, caching, consistency, failure modes |
| Behavioral loop | ownership, conflict handling, leadership signals | STAR stories with first-person actions and measured results |

## Preparation Rules

- Favor pattern recognition over brute-force memorization.
- Use the interview language the user is most fluent in; Python is often advantageous because of low syntax overhead.
- For senior roles, system design and behavioral articulation usually matter more than squeezing a few extra LeetCode mediums.
- Keep take-homes scoped, documented, and tested. Finishing cleanly beats sprawling ambition.

## Preparation Horizon

- If the user is already warm and needs only a refresh, 1-2 focused weeks may be enough.
- If the user is rebuilding coding, system design, and behavioral readiness from a cold start, expect roughly a 3-month cycle at about 10-12 focused hours per week.
- For senior loops, shift a larger share of that time toward system design, story quality, and mock-interview repetitions once baseline coding fluency is back.

## Live Coding Protocol

1. Clarify the prompt, constraints, and sample input or output before coding.
2. State a simple baseline approach first, then explain what would force optimization.
3. Code incrementally while narrating trade-offs, not just the final answer.
4. Test edge cases out loud before declaring the solution done.
5. Close with time and space complexity plus one next improvement if time allowed.

## Take-Home Submission Heuristics

- Timebox the work and choose a narrow MVP over sprawling ambition.
- Cover the critical paths with tests before polishing peripheral features.
- Ship a README with setup, assumptions, trade-offs, and what you would do next with more time.
- Leave known gaps explicit instead of pretending the exercise is production-complete.

## Behavioral Story Bank

Prepare 5-7 adaptable stories covering:

- conflict or disagreement
- deadline pressure
- technical debt trade-offs
- production failure or incident recovery
- mentorship or enabling others
- influence without authority
- difficult prioritization decision

Use strict STAR structure:

- **Situation:** enough context to understand scale
- **Task:** the specific objective or tension
- **Action:** what the user did, using "I" rather than "we"
- **Result:** quantified technical or business outcome

## System Design Interview Scaffold

Coach the user to:

1. clarify requirements and scale first
2. estimate traffic or capacity and name the core entities or API surface
3. propose a simple high-level design before optimizing
4. discuss storage, caching, consistency, fault tolerance, and observability
5. choose one meaningful deep dive
6. recap the trade-offs and why they match the stated constraints

## Using Reverse-Interview Time Well

Use this section to coach the user on how to spend question time well during an interview loop.

- Prepare 3-5 questions tied to unresolved decision risk, not generic filler.
- Adapt questions by interviewer role: engineers for delivery reality, managers for support and scope, directors for roadmap and org design.
- Use question time to test culture, expectations, and fit - not to perform cleverness.
- If the user needs an employer-evaluation question bank, load [company diagnostics](company-diagnostics.md).

## Coaching Moves

- If the user fails live coding from nerves: increase mock-interview frequency and narration practice.
- If they fail at senior loops: shift more time into system design and story quality.
- If they keep getting to final rounds but no offer: inspect reverse interviewing, story calibration, and company-fit narrative.
